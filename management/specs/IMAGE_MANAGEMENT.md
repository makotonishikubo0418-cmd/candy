# CANDY Image Management

- Updated: 2026-10-08
- Applies to: CANDY公開ページで使用する本文画像、一覧画像、OGP画像、再利用画像
- Status: Canonical common image specification

## 1. 目的と責任範囲

この管理書は、画像の選定、公開参照、HTML属性、代替テキスト、寸法、遅延読込、再利用、置換、実表示確認の共通要件を管理する。

エリア画像とホテル画像の生成条件、採用元保管、ペア管理、同名置換は、それぞれの `CANDY_AREA_IMAGE_*`、`CANDY_HOTEL_IMAGE_*` 管理書が正本である。女の子画像の公開状態は `CANDY_GIRL_INFORMATION_MANAGEMENT.md` が管理する。本書はそれらを上書きせず、ページへ組み込む共通条件だけを定義する。

## 2. 画像の選定と保存

1. ユーザーまたは原本で指定された画像を使用し、未承認の代替画像へ差し替えない。
2. 配置前に、対象ページ、ファイル名、拡張子、MIME、画素寸法、縦横比、向き、可読性を確認する。
3. 表示サイズに対して過大な画像は、意味と品質を損なわない範囲で適正化する。引き伸ばし、歪み、重要部分の欠落を禁止する。
4. 公開HTMLは公開用画像パスだけを参照し、`Text_*_data/画像データ/` の採用元を直接参照しない。
5. 既存画像を他ページでも使用するときは、同じ内容の重複コピーを無計画に作らず、正規公開ファイルを参照する。ページ固有の意味、切り抜き、画質、権利条件が異なる場合は別資産として管理する。

## 3. `src` と `alt` の絶対条件

- `src`、`srcset`、OGP `image`、JSON-LD `image` には画像のURLまたは相対パスだけを指定する。
- `alt` には画像内容とページ内の役割を表す代替テキストだけを指定する。ファイルパス、HTML、装飾記号、キーワード列を入れない。
- `alt` の文を `src`、`title`、`data-src` の代用にしてはいけない。
- 意味のある本文画像は、周囲の文章を読まなくても要点が分かる簡潔な `alt` を持つ。
- 純粋な装飾画像は `alt=""` とする。リンクまたはボタンとして機能する画像は、画像の外見ではなく遷移または操作の目的を伝える。
- 同じ画像を再利用しても、ページ内の役割が異なる場合は、その文脈に合う `alt` を設定する。
- CSS背景画像で意味を伝える場合は、既存実装に合わせて `role="img"` と適切な `aria-label` を設定する。装飾背景には不要な読み上げ名を付けない。

## 4. 既存遅延読込処理と `nolazy`

現在の共通JavaScript `HP/js/mdrwbpp2.4.js` は、`nolazy` を持たず、空でない `alt` を持つ `<img>` を独自遅延読込の対象にする。その処理は `alt` を一時的に `title` へ保存し、表示時に `title` の値を `src` へ代入して `alt` を空にする。

したがって、通常のHTML形式で正しい画像パスを `src` に、説明文を `alt` に指定した画像は、そのままでは説明文が画像URLとして `src` に代入され、表示が壊れる。

現行処理を別案件で修正し、既存全体への影響を検証するまでは、空でない `alt` を持つ新規または変更対象の公開画像に次を適用する。

```html
<img src="./imgHtml/example.jpg" class="nolazy" alt="画像内容を表す説明" width="1000" height="750" loading="lazy">
```

- `nolazy` は独自処理から除外するためのクラスであり、ブラウザ標準の `loading="lazy"` とは両立できる。
- 既存classがある場合は削除せず、class一覧へ `nolazy` を追加する。
- `alt` を空にして不具合を回避してはいけない。アクセシビリティとSEO要件を維持したまま独自処理から除外する。
- ソース上の `src` だけを見て表示成功と判断してはいけない。実DOMと画像の自然寸法を確認する。

## 5. 寸法、レスポンシブ表示、説明文

- 可能な限り実画像の縦横比に一致する `width` と `height` を指定し、レイアウトシフトを抑える。
- CSSで `max-width: 100%` と自動高さを維持し、PCとスマートフォンで横切れ、潰れ、過大な空白を発生させない。
- 主要画像は本文幅、画質、読み込み優先度を考慮する。画面外画像にブラウザ標準の遅延読込を使う場合も、実表示を確認する。
- 画像説明は `figure` と `figcaption` を基本とし、画像直下に適切な余白を設ける。中央揃えを機械的に使用せず、本文の読みやすさと画像の内容に合わせる。
- 説明文は画像から読み取れる内容の反復だけにせず、読者が画像を見る目的を短く補足する。

## 6. OGP、構造化データ、再利用

- OGPとJSON-LDの画像URLは、公開可能な絶対URLを使用し、HTML本文の主画像と意味を一致させる。
- 同じ公開画像を複数ページで使用する場合、置換の影響先を参照検索で特定する。1ページだけのつもりで共有画像を上書きしない。
- 同一URLの画像バイトを置換するときは、対象カテゴリの置換管理書と `CANDY_PRODUCTION_MIGRATION_MASTER.md` に従い、キャッシュ更新、参照更新、ロールバックを同じ単位で扱う。
- 画像名の大文字小文字、拡張子、相対階層を実ファイルと一致させる。Windows上で表示できても本番で一致するとは限らない。

## 7. 必須検証

ローカル作成では、対象画像ごとに次を確認する。

1. 参照先ファイルが存在し、読取可能で、想定形式と寸法を持つ。
2. HTMLの `src`、`alt`、`width`、`height`、classが意図どおりである。
3. 実DOMの `src` と `currentSrc` が画像URLであり、`alt` の文章へ書き換わっていない。
4. `img.complete === true`、`naturalWidth > 0`、`naturalHeight > 0` である。
5. スクロール前後、PC、スマートフォンで画像が表示され、縦横比、切り抜き、余白、説明文が適切である。
6. ブラウザコンソールとNetworkに画像404、MIME不一致、JavaScriptエラーがない。
7. OGPまたはJSON-LDで使用する場合、そのURLと本文主画像が一致する。

本番公開が指示された場合は、さらにproduction URLのHTTP成功、MIME、寸法、必要なSHA-256一致、実DOM、PC/SP表示を確認する。ローカル表示だけで本番表示済みと報告しない。

## 8. 停止条件

次の場合は、推測で補わず対象画像の作業を停止する。

- 原本画像、使用対象、権利、ファイル対応、表示目的を確定できない。
- 画像ファイルが欠落、破損、別内容、部分ペア、または想定外の形式である。
- 既存同名画像と内容が異なり、置換範囲、キャッシュ、ロールバックが未確定である。
- `src`、OGP、JSON-LD、一覧、複数ページの参照が競合する。
- 実DOMの `src` または `currentSrc` が画像URLではない、または自然寸法が0である。

## 9. 完了条件

- [ ] 正しい原本と公開用画像が対応している。
- [ ] `src` と `alt` の責任が混在していない。
- [ ] 現行の独自遅延読込対象となる説明付き画像に `nolazy` がある。
- [ ] 寸法、縦横比、レスポンシブ表示、画像説明が確認済みである。
- [ ] 再利用先と置換影響が確認済みである。
- [ ] 実DOM、自然寸法、Network、PC/SP表示が合格している。
- [ ] ローカル、Git、Actions、本番の状態を混同していない。
